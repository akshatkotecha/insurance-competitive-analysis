# Database structure

The schema for `INSURANCEDB`, scripted so the project can be rebuilt from
nothing. No database backup is committed: a `.bak` would be a large binary
nobody can read in a diff, and the premium data it carries is extracted from
insurers' own published PDFs rather than owned by this project.

## Running it

Select your target database first, then run the files in order. They contain
no `USE` statement on purpose, so they cannot redirect themselves at a
database you did not mean to touch.

```sql
-- in SSMS, with the target database selected
:r 01_schemas.sql
:r 02_tables.sql
:r 03_views.sql
:r 04_seed_reference_data.sql
```

Then populate the fact tables from the source PDFs:

```bash
python Python/extract_products.py   # seeds PRODUCT_MASTER
python Python/run_all.py            # PDFs -> raw -> clean -> PREMIUM
```

| File | Contents |
|---|---|
| `01_schemas.sql` | The three pipeline stages as schemas: `raw` → `clean` → `business` |
| `02_tables.sql` | 7 tables, primary keys, and the 7 foreign keys (added last, so table order can't break the script) |
| `03_views.sql` | 18 analysis views, topologically sorted so they create cleanly |
| `04_seed_reference_data.sql` | The 58 hand-curated rows: 8 insurers, their flagship products, 35 rows of published financials, 7 sets of policy-term flags |

`PREMIUM` (8,492 rows) and the raw/clean PDF text are **not** scripted — they
are extraction output, regenerated by the pipeline.

## Why the views matter

The `business` views are where the competitive-intelligence logic lives; the
Python layer only reads them.

- `vw_premium` → `vw_price_grid` → `vw_abhi_vs_market` computes the price
  index (ABHI premium ÷ competitor mean × 100) per age band and cover slab,
  carrying `competitor_count` so a comparison drawn against one rival can be
  told apart from a real market average.
- `vw_head_to_head` pairs ABHI against a single named rival on the segments
  both of them price.
- `vw_metrics_long` → `vw_metrics_growth` / `vw_metrics_cagr` /
  `vw_metric_rank` → `vw_abhi_scorecard` turns the wide financials table into
  a tidy series, then derives YoY, index-to-base, CAGR and peer rank.
- `vw_data_quality` and `vw_metric_coverage` report what the dataset cannot
  support — insurers with no premium rows, metrics with too few years.

Dependency order is enforced in `03_views.sql`; for example `vw_abhi_scorecard`
sits on top of `vw_metric_rank`, `vw_metrics_cagr`, `vw_metrics_growth` and
`vw_metrics_long`.

## Connection

Every script and the dashboard connect with Windows authentication to a local
SQL Server Express instance. The server name is currently hardcoded as
`AKSHAT\SQLEXPRESS`; change it in `Python/chatbot_core.py` (`CONN_STR`) and in
the pipeline scripts, or set it from an environment variable.
